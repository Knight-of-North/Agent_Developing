## 二、问题清单

### 🔴 中等（建议修，影响体验或正确性边缘）

**M1. AI 发言 prompt 的 JSON 示例缺少闭合引号**
- 位置：`nodes.py:612`
- 现状：示例里 `"speak": "你公开说的话（……也可隐瞒）` 末尾少了一个 `"`，示例本身不是合法 JSON。
- 影响：LLM 多数情况会自行纠正，但会提高输出非法 JSON 的概率，让 `_parse_json`/`_extract_speak` 兜底路径被更频繁触发（兜底虽安全，但会损失 think 里的推理质量）。
- 修法：给 speak 的值补上闭合引号即可，一字符修复。

**M2. "点名回应/追问"机制会打乱轮换顺序，有人被跳过、有人重复发言**
- 位置：`nodes.py:1027`（`suspects[round_num % len(suspects)]`）+ 各发言节点的 `phase_round + 1`
- 现状：`_current_speaker` 用 `phase_round % 人数` 决定轮换顺序，而**每一次发言（包括被点名插进来的回应、玩家追问）都会让 phase_round 前进 1**。推演实例：4 人局按 A→B→C→玩家 轮换，玩家点名 C 后，C 回应 +1、玩家追问 +1，接下来 `6 % 4 = 2` 又轮到 C——C 连续发言，而 A、B 的一轮被悄悄跳过。
- 影响：讨论公平性受损，玩家会感觉"怎么老是那个人在说"。功能不崩，但多玩几局能察觉。
- 修法（二选一）：① 给"被点名回应"单独加一个不递增 phase_round 的分支（回应不算正式轮次）；② 轮换指针从"轮次取模"改为"记录上一位发言者，取名单中的下一位"，彻底摆脱轮次耦合。推荐 ②，改动集中在 `_current_speaker` 一处。

**M3. 剧本 JSON 展示把 dict 直接传给 st.code，中文全变转义码**
- 位置：`app.py:202`（`st.code(script, language="json")`）
- 现状：`script` 是 dict，`st.code` 对它做 `str()` 转换，Python 的 dict 字符串化会把中文转成 `\uXXXX`，折叠面板里打开是一坨不可读的转义文本。
- 修法：`st.code(json.dumps(script, ensure_ascii=False, indent=2), language="json")`（文件顶部加 `import json`）。顺带可考虑去掉 `app.py:198` 那行原始 JSON 全文展示，避免同一内容显示两遍。

**M4. LLM 流式中断时静默降级，关键台词可能被截断且消耗轮次**
- 位置：`nodes.py:78-101`（`_stream_full_text` 默认 `allow_partial=True`）
- 现状：所有节点都用默认参数，网络断连时返回**半截文本**而不报错。对 AI 发言，半截 JSON 会走到"……（欲言又止）"占位并照常 `phase_round + 1`；对 `dm_reveal`（终局揭晓），半截文本意味着游戏最高潮被腰斩，玩家毫无察觉是网络问题。
- 修法：给 `dm_reveal`/`dm_intro` 这类不可截断的节点传 `allow_partial=False`（失败走 app.py 已有的错误提示+重试通道）；AI 发言保持现状（降级合理）。

### 🟡 低（值得修，但不紧急）

**L1. 文档与代码不同步（4 处）**
- `README.md:120` 标题写"14 个节点"，graph.py 实际注册 **13 个**（数一遍 add_node 即可确认）。
- `nodes.py:4-15` 模块 docstring 的节点清单停在 9 个，缺 self_intro / dm_midpoint / final_statement。
- `graph.py:5-12` 模块 docstring 的结构图缺 self_intro / dm_midpoint / final_statement 三个节点。
- `game_state.py:68` 注释说 user_role"由 generate_script_node 自动设为第一个嫌疑人"，实际早已改为用户自选（choose_role_node）。

**L2. `validate_role_choice` 是死代码**
- 位置：`interrupt_handler.py:39` 定义，全仓库无调用方。
- 后果：终端版 `main.py:90-94` 选角色时非法输入被 `choose_role_node` 静默兜底到第一个角色，用户得不到"输入无效"的提示。修法：main.py 选角色后调用它并在兜底时打印提示；或删掉这个函数。

**L3. requirements.txt 缺 pytest**
- README 和 tests/test_logic.py 都让用户跑 `pytest tests/`，但按 requirements 装完的环境没有 pytest。修法：加一行 `pytest>=7`（或单列 requirements-dev.txt）。

**L4. AI 投票只看最近 10 条消息**
- 位置：`nodes.py:793`（`[-10:]`）
- 现状：深入节奏（每人 4 轮）下讨论可达 24+ 条消息，AI 投票时已忘记前期线索，投票质量下降。修法：与 ai_player_turn 一样改为 `[-max(10, len(suspects) * 2):]`。

**L5. 最终陈词把完整 truth 交给发言者，可能提前剧透真凶**
- 位置：`nodes.py:883`
- 现状：被投最高者若是无辜者，prompt 里的 truth 含真凶姓名，LLM 喊冤时可能说出"真凶其实是 XX"。虽在揭晓前一刻、伤害有限，但会削弱 dm_reveal 的悬念。修法：无辜者版本的 prompt 只给"你不是凶手"这一事实，不给完整 truth。

**L6. 剧本生成重试时前端展示冗余**
- 位置：`nodes.py:216-239` + `app.py:184-189`
- 现状：自洽校验失败触发第二次生成时，第二份剧本的 token 会接在第一份后面继续 yield，展示框里出现两份 JSON 拼接。逻辑正确（最终取 return 值），仅显示冗余。修法：重试前通知前端清屏，或在 app.py 侧无法感知时接受现状（影响很小）。

**L7. 关系图弹窗高度不匹配**
- 位置：`app.py:28`（height=640）vs `visualization.py:109`（canvas 680px）
- 现状：弹窗里画布比容器高 40px，出现滚动条。修法：二处取齐（建议弹窗 height=700）。

**L8. 仓库整洁度小项**
- 根目录 `关系图优化预览.html` 是生成产物但被 git 跟踪，建议移入 docs/ 或取消跟踪并加入 .gitignore。
- 根目录 3 个诊断脚本（diag.py / diagnose.py / test_api.py）README 只介绍了 diagnose.py，另两个建议在 README 补一句或收进 `scripts/` 目录。
- `.vscode/tasks.json` 是别的 C++ 项目遗留的任务配置（与本项目无关），虽已被忽略不会提交，可顺手清理。

## 三、全局结构评估（仓库健康度）

从全局视角看，仓库结构是**健康且持续改善的**：

1. **模块分层清晰**：names（数据）/ prompts（提示词）/ validators（确定性兜底）/ visualization（展示）/ interrupt_handler（交互复用）各司其职，nodes.py 虽仍有 1063 行但已是纯编排层，"LLM 生成 vs 确定性校验"的分界线在每个文件里都保持得很干净。
2. **双入口对齐**：app.py（Web）与 main.py（终端）的功能已对齐——动作系统（公开线索/指控/调查）、讨论节奏选择在终端版都有对应实现，没有出现"Web 版独占功能"的分裂。
3. **测试成为资产**：88 个测试全部针对纯函数与确定性节点（不烧 token），且每个历史踩坑点（中文分号、平票、think 泄露、holder 写错、关系图崩溃）都有回归用例钉住，这是防回归的正确姿势。
4. **文档归档合理**：历次审查/评估/调研报告已归档进 docs/ 并被 git 跟踪，README 的结构图、FAQ、快速开始与当前代码基本一致（除 L1 列出的 4 处滞后）。
5. **遗留缺口**：测试全部集中在确定性逻辑，**图流程本身（节点串联、interrupt 恢复、路由闭环）没有任何不烧 token 的 mock 测试**——M2 这类路由层问题正是测试盲区。长期可考虑用 fake LLM（返回固定 JSON 的桩对象）跑通一整局做端到端冒烟测试，这是目前测试体系唯一值得规划的方向。
